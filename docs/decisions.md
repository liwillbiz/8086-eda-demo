## M0 build and interface choices

- **CMake ≥ 3.25, not 3.24.** `cmake --workflow` (used by `./regress`) needs preset schema v6, which needs 3.25.
- **Schema validation** will be a hand-written validator in `libs/spec`, run under `ctest` (M1). `spec/schema/spec.schema.json` documents the shape for editors and reviewers; we don't add a JSON-Schema library.
- **Stubs throw `i8086::NotImplemented`** (in the header-only `libs/common`, which was added for this). The runner reports it as **Error**, never Fail, so an unfinished layer can't look like a device defect. Each message names the milestone that replaces it (for example `[M4]`).
- **`Spec` uses pimpl** (`shared_ptr<const Impl>`), so it is cheap to copy and M1 can change storage without editing the frozen header.
- **`FaultInjector` is a `DeviceModel` decorator** (`model/fault_injector.hpp`) that applies the pin-level faults (StuckAt, SlowTiming, SetupDegrade, LowVccFail). `LogicBug` is passed into the behavioral core, and `Leaky` is consumed by `tester::ElectricalModel`. `make_behavioral()` always returns the core wrapped in a `FaultInjector`.
- **Golden independence is enforced by the build:** `i86golden` links only `i86::common`, never `i86::model`. It has its own `Registers` and `Program` types.
- **Additions to the design doc sketches:**
  - `Tester::set_temperature()`, because the sketch had no way to set TA for the VCC × TA matrix.
  - `measure_time(EdgeRef from, EdgeRef to)`: the pin moved into `EdgeRef`, so a measurement can span two pins (for example CLK → ALE).
  - `TestContext` also carries `vcc_v` and `temp_c`.
  - `Spec::grade()` returns `fclk_max` and the TCLCL range.
  - `TestCase::spec_symbols()` is optional.
- **Datalog JSON** uses generic `value` / `min` / `max` / `unit` keys instead of unit-suffixed keys such as `value_ns`.
- **Test cases are compiled as a CMake OBJECT library** (`i86cases`, globbed from `testprog/cases/**.cpp`), so `REGISTER_TEST` static initializers are never dropped by the linker.
- **Pin names** use the minimum-mode name with `_N` for active-low pins (`RD_N`, `M_IO_N`). Pin 20 is `GND2` so that names stay unique.
- **Baselines:** `./regress` diffs `out/good/results.csv` against `regression/baselines/good_results.csv`. It is header-only until test cases exist; shmoo baselines come in M6.
- **Interface change policy:** the headers under `libs/*/include` and `testprog/include` are frozen. Additive changes are fine through a PR reviewed by the Spec & Integration lead and the owner of that header (enforced by CODEOWNERS). Breaking changes need every affected owner.

## M1 spec choices

- **No frozen header changed.** `spec.hpp` is identical to M0; everything new lives behind `Spec::Impl`.
- **Expressions** support `+ - * /`, parentheses, numbers, and variables. AC bounds may use `TCLCL` (the period passed to `Spec::ac()`) and `SYM.min` / `SYM.max` of another AC parameter at the same grade and period (for example `TLHLL = TCLCH.min - 20`). A limit that references an unverified limit is itself reported as unverified. `Spec::ac("TCLCL", …)` returns the `grades` range, so TCLCL is not duplicated under `ac`.
- **`Spec::ac()` evaluates at any positive period**, including periods outside the grade's range, because the shmoo sweeps below the grade minimum.
- **VCC-relative DC limits** (`VIH max = VCC + 0.5`, `VCH max = VCC + 1.0`): `Spec::dc(sym, Grade)` has no VCC argument, so it returns the bound that holds over the whole `conditions.VCC` range (a max takes its smallest value, a min its largest). Today that gives VIH max = 5.0 V and VCH max = 5.5 V. If M6 needs the limit at the actual test VCC, add an overload `dc(sym, Grade, double vcc_v)`; the expressions are already stored.
- **`conditions`** (VCC, TA, AC test levels and load) are loaded and validated, and VCC drives the DC evaluation above. There is no public accessor yet; M4/M6 can add `Limit condition(std::string_view) const` additively if the tester needs them.
- **`dc.*.cond`** (for example `IOL_mA: 2.5`) is validated but not exposed through `Limit`.
- **Decode tables** hold stable identifiers (`int_ack`, `mem_read`, `CS_or_none`, `high_byte`, …), not prose, so the protocol checker can compare strings.
- **`verified: false`** marks every value the brief flags "(verify)": the whole of brief §6.1 and §6.2 (and the VCC/TA conditions they share), the clock measurement levels in the AC test conditions, and the individual §4.2 cells (8086-1 TDVCL, TCLAV, TCLRL, TCLRH; 8086-2/-1 TCHRYX and TINVCH). The 8086-1 TCLRL/TCLRH cells have no value in the brief; they carry the 8086-2 values as placeholders until X1.
- **8086-1 TCLCH and TCHCL** are the fixed 53 ns and 39 ns the brief prints, not the formula (which would give 51.7 ns and 35.3 ns at 100 ns). The 8086 and 8086-2 columns use the formula.
- **Validation is strict**: unknown or duplicate keys, missing `ref`/`verified`, unknown units, bad expressions, unknown variables or references, reference cycles, min > max at either end of a grade's clock range, incomplete decode tables, and pin-table errors all fail `Spec::load` with `file:line`. `libs/spec/tests/validation_test.cpp` covers each rule by mutating the real `spec.yaml`.

## M2 golden emulator choices

- **No frozen header changed.** `emulator.hpp` is identical to M0; the core lives in `libs/golden/src/cpu.{hpp,cpp}`. One **additive** header, `golden/rom.hpp`, adds the ROM loader (`read_binary`, `rom_program`, `load_rom`). It places a flat binary so that its last byte is at FFFFFh, which puts the reset entry FFFF0h 16 bytes from its end. Because it is under `libs/golden/include/`, CODEOWNERS asks the Spec & Integration lead to review it.
- **Coverage:** the full §7.3 subset, plus most of the rest of the 8086 ISA, because the decode is shared: all ALU forms, SBB/NEG/NOT/TEST, every shift and rotate, MUL/IMUL/IDIV, the BCD adjusts, every string op with REP/REPE/REPNE, LOOP*/JCXZ, XCHG, LEA, LDS/LES, CBW/CWD, LAHF/SAHF, XLAT, INT 3/INTO. **`StopReason::Unimplemented`** covers WAIT (TEST# is not part of a `Program`), the undocumented D0–D3 /6, FE /2–/7, FF /7, 8F/C6/C7 with reg ≠ 0, and LEA/LDS/LES/far CALL/far JMP with a register operand. ESC (D8–DF) decodes its operand and does nothing, which is what an 8086 does without an 8087.
- **Undocumented opcodes that are implemented** (brief D11): `0F` = POP CS, `D6` = SALC (AL = CF ? FFh : 00h), `60–6F` = aliases of `70–7F`, `C0/C1/C8/C9` = aliases of `C2/C3/CA/CB`, `82` = alias of `80`, `F1` = LOCK, F6/F7 /1 = TEST. 8C/8E decode only the low two bits of the segment field, so `MOV CS,r/m` is legal and acts as a jump. None of these raise type 6.
- **Stop semantics.** HLT counts as an instruction, and IP is left past it. On Unimplemented, nothing has changed, IP points at the start of the instruction (its first prefix), and the instruction is not counted. On InstructionLimit, `instructions == max_instructions`.
- **Memory** is 1 MB of zero-filled RAM. `Program::segments` is copied in order, wrapping at 1 MB. Every byte write is recorded in `mem_writes` in program order, including stack pushes and interrupt frames; a word write is two records, low byte first. Word accesses wrap **inside the segment** (a word at `xxxx:FFFF` uses `xxxx:0000` for its high byte). Physical addresses wrap at 1 MB (D5).
- **I/O.** `IN` reads `Program::io_inputs[port]`: the whole 16-bit value for a word IN, and its low byte for a byte IN. A port that is not listed reads as an undriven bus (FFh / FFFFh). Every OUT is one `IoWrite` record.
- **FLAGS representation.** `Result::regs.flags` holds only the nine real flags (mask 0FD5h), which matches `reset_registers()` (flags = 0). Bits 15–12 and bit 1 read as 1 wherever FLAGS reaches memory or AH: PUSHF, interrupt frames, and LAHF (D9). POPF, IRET, and SAHF store only the nine flags.
- **Undefined flags are left unchanged.** The model may legitimately differ, so the M5 model-vs-golden comparison must mask these per instruction:

  | Instruction | Undefined (golden leaves unchanged) |
  |---|---|
  | AND, OR, XOR, TEST | AF |
  | SHL/SHR/SAR | AF; OF when count ≠ 1 |
  | ROL/ROR/RCL/RCR | OF when count ≠ 1 |
  | MUL, IMUL | SF, ZF, AF, PF |
  | DIV, IDIV | all six arithmetic flags |
  | AAA, AAS | OF, SF, ZF, PF |
  | DAA, DAS | OF |
  | AAM, AAD | OF, AF, CF |

  A shift or rotate with a count of 0 changes no flags. The count is never masked (D8).
- **Interrupts.** `InterruptEntry::instruction_index` is the 0-based index of the instruction that raised the interrupt (INT n, INT 3, INTO, divide error), or of the instruction after which the single-step trap was taken. The divide error stacks the IP of the instruction **after** DIV/IDIV/AAM (D3). The IDIV quotient range is ±127 / ±32767: a quotient of −128 / −32768 raises type 0 on the 8086.
- **Single step (TF).** A type-1 trap follows every instruction that *started* with TF = 1, except an instruction that itself entered an interrupt, HLT (the run stops), and any segment-register load (MOV sreg, POP sreg), which on the 8086 inhibits the trap for one instruction. So POPF setting TF traps after the *next* instruction, and IRET into a TF = 1 context traps after the first instruction there (D10).
- **Known simplifications.** A REP string instruction runs to completion as one instruction; on silicon a TF trap can split it per iteration. A `Program` has no INTR, NMI, HOLD, or TEST# stimulus, so the golden cannot predict A4, A5, or D7 as-is. M8 will need an additive field on `Program` (for example, interrupt requests keyed by instruction index), which means a frozen-header review.
- **Tests** (`libs/golden/tests`): brief D1–D6 and D8–D11 vectors, a shift/rotate table, multiply/divide/BCD cases, control flow, strings, I/O capture, and the ROM loader. `flags_table_test.cpp` runs ADD/ADC/SUB/SBB/CMP/INC/DEC/NEG over every 8-bit operand pair (with and without CF in) and over 4 000 16-bit edge and fixed-seed random pairs. Results are checked against a reference written with plain signed arithmetic, and reported by the emulated program through PUSHF and OUT.

## M3 model choices

- **No frozen header changed.** The behavioral core lives in `libs/model/src/behavioral/` (`core.hpp`, `core_biu.cpp`, `core_eu.cpp`). `FaultInjector` is still a pass-through decorator; M7 fills it in.
- **Edge contract.** Every T-state starts on a CLK **falling** edge: `clock_edge(Falling)` runs the EU for one clock, then advances the BIU (T1→T2→T3→Tw…→T4→T1/Ti). `clock_edge(Rising)` ends the ALE pulse, samples RESET, READY (in T3/Tw), INTR, NMI, HOLD and MN/MX#, commits read data (T4), and picks the next bus cycle, driving M/IO# and DT/R# before T1.
- **Pin events.** Each delay is a die symbol from `timing_ns`, applied at the edge the datasheet measures it from: AD/A/BHE# address at T1 and A19–A16 status at T2 (`TCLAV`), ALE (`TCLLH` / `TCHLL`), RD# (`TCLRL` / `TCLRH`), WR# and DEN# (`TCVCTV` / `TCVCTX`), M/IO# and DT/R# (`TCHCTV`), AD float (`TCLAZ`), and write data (`TCLDV`). The die profile may therefore hold datasheet symbols that `spec.yaml` doesn't have yet. A missing key fails `make_behavioral` with `SpecError`. The first `clock_edge()` reports the level of every output pin at delay 0, and later edges report only changes. **Output delays are reported nominal**: SimTester multiplies every `PinEvent` delay by `ElectricalModel::derate()` (M4 contract), so the model must not.
- **Inputs.** `set_inputs` updates only the pins it is given; the others keep their level (power-on: READY = MN/MX# = 1, AD = Z, the rest 0). Each sample's `changed_ps` is checked against the die requirement at the sampling edge: read data `TDVCL` at the falling edge that starts T4, READY `TRYHCH`, and INTR/NMI/HOLD `TINVCH` at the rising edge. The **hold** check (`TCLDX`, `TCHRYX`) runs on the next `set_inputs`: a change within the hold window after the edge spoils the latch. The model derates only these setup/hold windows (`TDVCL`, `TCLDX`, `TRYHCH`, `TCHRYX`, `TINVCH`) in `set_conditions`, using the same formula and die keys as `ElectricalModel` (`derate_vnom_v`, `derate_vt_v`, `derate_alpha`, `derate_beta_per_c`; `domain_error` on `vcc <= vt` or `k <= 0`). The model can't call the tester layer, so the formula is duplicated; keep the two in step. To place a hold-window change relative to the edge, the model measures the spacing between consecutive edges from the samples themselves: an input that didn't change has `changed_ps` shifted by exactly the gap between edges (M4 sends every input at every edge). If no pin gives a measurement it falls back to the spec's 33% CLK (low 2/3, high 1/3). This means `Conditions` doesn't need a `clk_high_ns` field.
- **X becomes wrong data.** A data bit latched as X resolves to the inverse of the level being driven, and an undriven bit (Z) reads as 1. That makes a setup or hold violation always visible downstream. A READY latched as X counts as not ready and inserts an extra Tw.
- **Bus details.** Words at even addresses take one cycle; words at odd addresses (memory or I/O) take two byte cycles, odd byte first. A byte write is driven on both lanes, and BHE#/A0 says which lane is valid. BHE#/S7 holds its T1 value (S7 is not modeled). S5 = IF, S6 = 0. Vector reads use S4 S3 = 10 ("none"). Halt is an ALE pulse with no strobes, followed by Ti; `BusCycleType::Halt` covers its T1.
- **RESET** is sampled on rising edges without a setup check (the 8284A synchronizes it). While RESET is high, 3-state outputs float, ALE and HLDA are 0, and INTA# is 1. The first T1 (code fetch at FFFF0h) starts 7 CLK after the falling edge that precedes the first low sample (brief §5). The model powers up as if RESET had just been released. A model that threw stays failed until RESET.
- **Prefetch queue.** A word fetch runs from an even IP and a byte fetch from an odd IP, only when at least 2 bytes are free. The queue therefore stops at 5 bytes when the EU has consumed an odd number of bytes. A flush discards an in-flight fetch's data.
- **EU** is a C++20 coroutine, so instruction code reads sequentially and suspends on queue bytes, bus cycles, and EU clocks. Clock counts are approximate and deterministic; the datasheet has none. Implemented: the §7.3 subset plus SBB (same ALU encoding group), INTO, single-step (TF), `0Fh` POP CS and `8Eh /1` MOV CS (these flush the queue and continue at the new CS:IP, unlike silicon, so that they match an instruction-level emulator), and `D6h` as SALC (AL = CF ? FFh : 00h, no trap). Everything else raises `UnimplementedInstruction`.
- **Undefined flags**, for the golden owner's differential fuzz to mask or match: AND/OR/XOR clear AF; shifts leave AF unchanged; for shift counts above 1, OF follows the last single-bit step; DIV leaves all flags unchanged.
- **Later milestones report `NotImplemented`** (Error, not Fail): INTR with IF = 1, a rising NMI edge, HOLD high (M8), and MN/MX# = 0 (M9).
- **LogicBug** names in the core are `inc_clears_cf` and `shift_count_masked`. An unknown name throws `NotImplemented` (M7 adds more).
- **`libs/model/tests/harness.{hpp,cpp}`** is a small memory-emulation driver: it decodes the address from the pins when ALE falls, serves memory and I/O, holds READY low, and controls data setup and hold. It shows the input protocol `SimTester` (M4) needs to follow.

## M4 tester choices

- **No frozen header changed.** `tester.hpp`, `sim_tester.hpp`, `pattern.hpp`, `memory_image.hpp`, `electrical_model.hpp` and `spec.hpp` are identical to M1. The optional `Spec::dc(sym, Grade, vcc_v)` and `Spec::condition(sym)` were not needed and were not added.
- **Clock and time base.** A CLK period starts at the CLK falling edge (the start of a T-state); CLK rises `period - clk_high` later. Every time is integer ps. `TimingSet::clk_high_ns = 0` means the middle of the window that meets `TCHCL.min` and `TCLCL - TCLCH.min` for every grade at that period (75.17 ns at 200 ns), falling back to `TCLCL/3` if the window is empty.
- **Input sampling.** Before each edge the tester passes every input and I/O pin to `DeviceModel::set_inputs` with the value driven strictly before the edge and `changed_ps` = time of that change minus the edge (≤ 0). A drive exactly on an edge is seen by the next edge. The model applies its own setup/hold windows (and their derating).
- **Derating.** `SimTester` multiplies every `PinEvent::delay_ps` the model reports by `ElectricalModel::derate(conditions)`, so the model reports nominal (die and fault-adjusted) delays. `ElectricalModel::load_delay_ps` is implemented but not applied yet: the `Tester` API has no way to program CL. M6 decides how B5 sets it.
- **`last_trace()`.** `TraceCycle::events` holds every change of the *resolved* pin value (tester drive merged with DUT drive, contention = X), including the tester-generated CLK. In the trace, `PinEvent::delay_ps` is **absolute ps since the start of the run**, not relative to an edge. `TraceCycle::bus` is `DeviceModel::bus_state()` after that period's rising edge. `measure_time` counts a change to 1 as a rise and a change to 0 as a fall, from any previous value (including X/Z at power-on), and occurrences are counted over the whole trace.
- **Bus decode from pins.** Transactions are decoded from the pins like a logic analyzer would (min mode): an ALE 1→0 latches the address/BHE#/M/IO#, the first RD#/WR#/INTA# fall classifies the cycle, its rise marks T4. A cycle with no strobe by the end of T3 is a Halt. `bus_state()` is used only to label a memory read as `CodeFetch`. Read data is what was on AD at the falling edge that starts T4, and write data is what was on AD just before WR# rose. `wait_states` = T4 − T1 − 3, as observed. The decoder also runs, passively, in vector mode.
- **Memory-emulation mode** (`run_program`): RESET is held high for 4 CLKs (brief §3.1); MN/MX# = 1, READY = 1, INTR = NMI = HOLD = TEST# = 0. The tester is RAM and I/O: it serves reads on the enabled byte lanes from a copy of the image, and writes update that copy (and a separate 64 K I/O space, which `IN` reads back). Unmapped bytes float (Z). Read data is driven at the AD pins' `drive_ns` into T3 and released at the end of T4. READY goes low at READY's `drive_ns` into T2 for `wait_states` CLKs. `pass` = halted (if `stop_on_halt`) within `max_cycles`. An image without a byte at FFFF0h is rejected (`std::invalid_argument`), so it reports as Error.
- **Vector mode** (`run_pattern`): one vector repeat = one period. Drive `0`/`1` is VIL/VIH through `ElectricalModel::input_level`; `Z` turns the driver off; `X` on an input keeps the previous drive. RZ returns to 0 (R1 to 1) at the end of the period. On I/O pins a compare char turns the driver off at the drive edge. `H`/`L` compare `output_voltage(pin, level, IOH or IOL)` against VOH/VOL at the strobe edge; `M` expects Z; `C` is not compared (read the value from `last_trace()`). `VectorFail::vector` is the expanded period index and `strobe_ps` is absolute.
- **`.pat` timing attributes:** `period`, `clk_high`, `drive`, `strobe`, `fmt` (NRZ/RZ/R1), `grade`, and per-pin `drive.PIN`, `strobe.PIN`, `fmt.PIN`. Values are expressions in ns (`ps`/`us` suffixes allowed). `TCLCL` is the period of the tester timing set with the same id (or the resolved `period` in the other attributes), and `SYM.min`/`SYM.max` evaluate `Spec::ac` at that period. Because the `Tester` API carries no grade, a pattern that references `SYM.min`/`.max` must say `grade=…`. Precedence: per-pin attribute > pattern-wide attribute > `TimingSet::pins` (by pin name, then by bus name such as `AD`) > `PinTiming{}`.
- **Guards.** `set_levels` checks VCC/VIH/VIL against `abs_max.V_PIN`. `set_temperature` checks `TSTG` while unpowered and `TA_BIAS` while powered, and `power(true)` checks `TA_BIAS`. Out-of-range values throw `std::out_of_range`; bad timing throws `std::invalid_argument`; running or measuring with power off throws `std::logic_error`.
- **`ElectricalModel`** implements design doc §5.2 from `die.electrical` keys (`vin_threshold_v`, `vin_band_v`, `vol_offset_v`, `ron_low_ohm`, `voh_drop_v`, `ron_high_ohm`, `leak_ua`, `load_slope_ns_per_pf`, `derate_vnom_v`, `derate_vt_v`, `derate_alpha`, `derate_beta_per_c`, `icc_base_ma`, `icc_ma_per_v`, `icc_ma_per_c`; `KEY.PIN` overrides `KEY` for one pin) plus `Leaky` faults. A missing key gives an ideal part, so today's empty `good.yaml` behaves like the M0 stub. M6 fills the die values. The PMU methods (`force_i_measure_v`, `force_v_measure_i`, `measure_icc`) pass straight through to it.

## M5 test program choices

- **No frozen header changed.** Everything new is layer-private under `testprog/src/` (harness, protocol checker, `RomCase`) and `testprog/cases/`.
- **Integration.** M5 is the first branch that merges M2 (golden), M3 (model) and M4 (tester). The three layers worked together through the frozen interfaces without any cross-layer code fix. The only merge conflicts were the per-milestone sections of this file.
- **Test ROMs (D7).** `testprog/roms/*.asm` (NASM, `cpu 8086`, `-f bin`) are assembled at build time and **embedded** into `i86testprog` along with `testprog/patterns/*.pat` (`cmake/EmbedFiles.cmake`), so `i86test` needs no paths at run time. Each ROM is 4 KB at FF000h (CS = FF00h) with a far jump at FFFF0h and HLT padding. RAM: vector table at 00000h, stack at 00F00h–00FFFh, data from 02000h. A ROM must write RAM before it reads it, because the golden emulator's RAM reads 00h and the tester's unwritten RAM floats. The conventions live in `roms/inc/i86rom.inc`. Without NASM, the configure step warns and ROM-based tests report **Error**. The `regress` preset sets `I86_REQUIRE_NASM=ON`, and CI installs `nasm`.
- **Results leave the CPU only through OUT.** ROMs report words to port E0h (compared exactly) and FLAGS images to E2h (compared under the test's undefined-flag mask). The test program never reads `DeviceModel::arch_state()`. It sees only `Tester`, so the model's state is reconstructed from the I/O and memory write cycles that the tester decodes from the pins.
- **Model-vs-golden diff** (`diff()` in `testprog/src/functional.cpp`): halt status, then the I/O writes as an ordered byte stream (a word is its low byte, then its high byte), then the memory writes as an ordered byte stream. Bytes in the stack window are compared **by count only**, because they can hold FLAGS images with undefined bits; a ROM pops and reports anything on the stack that it wants checked. **Undefined flags are masked** per test (D3: all six arithmetic flags after DIV; D8: AF and OF after a multi-bit shift) or per report (the fuzz test). With the masks removed, the fuzz shows exactly the expected differences: AF after AND/OR/XOR (the golden leaves it unchanged, the model clears it) and OF after shifts with a count above 1.
- **Every ROM test is judged four ways** (`RomCase`): the DUT halted; the protocol checker reports no violations; the DUT matches the golden prediction; and the brief's own expected values hold (design doc §14: brief-derived values guard against a common-mode golden/model bug). Each judgement is a datalog record, and a failing row's `results.csv` message is the first failing record.
- **Protocol checker** (`testprog/src/protocol.cpp`), per decoded bus cycle: T-state order T1 T2 T3 Tw* T4 (from `TraceCycle::bus`); one ALE pulse in T1; the cycle's strobe falls in T2 and rises in T4, and no other strobe moves; DEN# is active from T1/T2 to T4; DT/R# and M/IO# match the cycle type; S6 = 0; a code fetch reports segment `CS_or_none`; BHE#/A0 is never `none`. Status pins are read just before the strobe rises. Every A and D test runs it.
- **Functional timing** (`functional_timing()`): timing set 0 runs at the grade's fastest clock (`TCLCL` min) with the tester's default duty cycle and read data driven at the start of T3. Functional tests are therefore at Fmax for the grade at every VCC × TA point.
- **A1** runs `patterns/reset_vector.pat` in vector mode (the test sets the pattern's `grade` attribute to the grade under test, so `TCLAV.max` follows the grade), then the boot ROM in memory-emulation mode. Checks: the first bus cycle is a code fetch at FFFF0h, and RESET-fall-to-first-T1 is 7 ± 1 CLK. That window is our reading of the brief's "about 7 clocks", so it is logged as `verified: false` and shows in the unverified-limit banner.
- **A3** checks the BHE#/A0 code of each of the ten data cycles against `spec.decode.byte_enable` identifiers, including the odd-word split (odd byte first, then even). **D4** reads S4/S3 from the A17/A16 pins during each read and decodes them through `spec.decode.segment`.
- **Differential fuzz** (`testprog/tests/differential_fuzz_test.cpp`): 64 programs × 40 instructions (seed 8086) from the §7.3 subset: ALU reg/mem/imm forms (ADD OR ADC SBB AND SUB XOR CMP), INC/DEC, SHL/SHR by CL with a known count, MOV, PUSH/POP, CLC/STC. AX BX CX DX SI DI BP and FLAGS are reported after each instruction, and the data area is reported at the end. Memory operands use direct addressing into an initialized data area, so no uninitialized RAM is read.
- **Open: shift by CL = 0 on a memory operand.** The golden emulator writes the unchanged operand back; the model runs no write cycle. Register and FLAGS results agree. The brief doesn't decide it. The fuzz excludes that one form (it uses count 1 instead) until the golden and model owners agree on the 8086 behaviour.
- **Fault detection** (`testprog/tests/cases_test.cpp`): with the model's `inc_clears_cf` LogicBug only D2 fails, and with `shift_count_masked` only D8 fails. Each is caught by both the golden diff and the brief value. Die-file faults are M7, so these faults are injected through `make_behavioral()`.
- **Summary report**: results matrix per grade (test × VCC × TA), a failures table, a worst-margin table for non-exact limits, and the unverified-limit banner listing each test and parameter with its limit reference. The `results.csv` format (and so the baseline) is unchanged.

## M6 timing, electrical and shmoo choices

- **Frozen header change (additive, needs tester-owner and Spec-lead review).** `tester::LevelSet` gains `vch`/`vcl` (CLK drive levels, default 3.9 V / 0.6 V) and `cl_pf` (load on every output, default 0 pF). Defaults keep every M5 result unchanged. `set_levels` checks VCH/VCL against `abs_max.V_PIN` and rejects a negative or non-finite load. This answers M4's open question of how B5 sets CL.
- **Tester (`engine.cpp`).** A driven (0/1) DUT edge is delayed by `ElectricalModel::load_delay_ps(pin, cl_pf)` after derating; floating (Z) edges are not loaded. CLK goes through `input_level("CLK", vch or vcl)`. The DUT gets an edge only when that level crosses the die's CLK threshold from its last seen level. A level inside the band or on the wrong side leaves the DUT's clock where it was (so the clock stops, as on a real part). An earlier draft skipped only the unresolved edges. The model then received many rising edges in a row, and the next run on the same DUT failed.
- **Model (cross-layer, smallest fix, to port to the model owner).**
  1. Optional die key `timing_ns.TCLCL_CRIT` is the die's internal critical path at 5 V / 25 °C, derated with the same k(VCC,T) as its setup windows. When the clock period is shorter, write data never settles and the model drives X on AD for the data phase of every write. Without it nothing in the model limits frequency, so B1 and the shmoo would have no Fmax edge. A missing key means no limit.
  2. A stored fault (an `UnimplementedInstruction` from garbage read data in a search) was re-raised whenever RESET was not high. A new `run_program` starts with RESET undriven at the first edge, because a drive at t = 0 is seen from the next edge. So every later run on the same DUT failed. The model now re-raises only on RESET low, and an edge with RESET undriven does nothing.
- **Die profiles.** `good.yaml` now has electrical values: k = 1.33 at 4.5 V / 70 °C, inputs switching at 1.4 ± 0.1 V, VOL 0.25 V, VOH 3.78 V at 4.5 V, 0.5 µA leakage, 0.03 ns/pF, ICC 260 mA nominal. Its `TCLAV` drops from 35 to 30 ns so B5 holds at 8086-1 with 100 pF (35 × 1.33 + 3 = 49.6 ns had only 0.4 ns margin). `TCLCL_CRIT` is 62 ns. The new `marginal.yaml` passes every test but sits close to the limits at the worst corner: TCLAV 48 of 50 ns, TDVCL 4.8 of 5 ns, critical path 96 of 100 ns, VIH switch 1.9 of 2.0 V, VOL 0.425 of 0.45 V, ICC 327.5 of 340 mA.
- **Shared harness** (`testprog/src/margin.{hpp,cpp}`). `rom_outcome()` runs one ROM and passes only if the DUT halts, matches golden, and breaks no protocol rule. An exception (abs-max guard, bad timing set) counts as a fail, so searches can step outside the legal range. Runs give up after 10 000 CLKs. `find_edge()` wraps `search_pass_fail` and returns nothing when the start point already fails. `functional_suite()` is boot, the B1 checksum, A3 and every D ROM with its D-case flag mask; C6 and the shmoo use it.
- **B1 checksum ROM** (`roms/b1_checksum.asm`). It copies 32 words of ROM to RAM, then folds them with ADD, XOR and a rotate done as `add dx,dx` / `adc dx,0`, and finishes with a DIV. It uses only the v1 subset (no LODS, LOOP, ROL or MUL) and so exercises reads, writes and the EU.
- **How each test judges.** A search records the die's actual edge, judged against the spec bound the die must beat: a required setup or pulse must be at most the spec minimum, and a switching level must sit inside VIH min / VIL max. Every search is preceded by a run at exactly the spec value, which must pass.
  - **B1:** checksum at TCLCL 500, 400 … grade min, then a search for the shortest passing period (≤ grade TCLCL min, note gives Fmax).
  - **B2:** pass at CLK high = TCHCL min and low = TCLCH min, then search each phase down.
  - **B3:** read data driven `period − setup` into T3; required setup ≤ TDVCL min.
  - **B4:** 1–3 Tw with READY back high exactly TRYHCH min before the sampling edge; every bus cycle has exactly N Tw; required READY setup ≤ TRYHCH min. The hold is tester-applied (one READY edge per period cannot shrink it on its own), logged against TCHRYX min.
  - **B5:** CL = 100 pF; worst over all cycles of TLHLL, TRLRH, TWLWH, TRHAV (min) and TCLAV (min and max), computed from `last_trace()` edges.
  - **C1:** the boot ROM is stopped after each of CLK 6–48 and every output in a 0/1 state gets IOL 2.5 mA or IOH −400 µA. AD pins are measured only in T1 or write cycles, when the DUT drives them. Outputs never seen low or high (INTA#, HLDA, …) are logged without a limit.
  - **C2:** all inputs at VIH 2.0 / VIL 0.8 V, then a search for each switching point.
  - **C3:** 0 V and VCC on every input.
  - **C4:** `patterns/reset_float.pat` holds RESET; 0.45 V and VCC on every 3-state pin; a pin still driven counts as a fail.
  - **C5:** ICC after the checksum at the grade's Fmax, at the matrix point.
  - **C6:** the functional suite at the matrix point, plus the highest applied voltage against V_PIN and TA against TA_BIAS.
  - **C7:** CLK at VCH 3.9 / VCL 0.6 V, then a search for each CLK switching point.
- **B6 (TINVCH) is deferred to M8.** The model's INTR with IF = 1, NMI and HOLD throw `NotImplemented` until M8, so B6 is not registered yet.
- **Values the `Spec` API does not expose.** `conditions:` (AC_CL = 100 pF, VCC 4.5–5.5 V) is not reachable through `spec::Spec`; M4 left `Spec::condition()` unadded. B5 hard-codes 100 pF and the shmoo hard-codes the 4.5–5.5 V box, each citing `spec.yaml conditions`. Adding `Spec::condition()` would remove both.
- **Shmoo** (`testprog/src/shmoo.cpp`, writers in `testprog/report/shmoo.cpp`, `i86test --shmoo`):
  - **Grid:** VCC 4.0–6.0 V in 0.25 V steps (clamped to V_PIN) × 2–12 MHz in 1 MHz steps plus 12.5 MHz (TCLCL 80 ns), at 25 °C (or the first `--temp`).
  - **Cells:** each runs the functional suite on a fresh DUT and stops at the first failing ROM.
  - **Outputs:** `shmoo.csv` (`vcc_v,mhz,tclcl_ns,result,first_fail`), `shmoo.txt` and `shmoo.svg`. The ASCII plot marks the fastest grade's box with `[ ]`, and `X` is a fail inside any grade box. The SVG draws all three grade boxes, with a tooltip per cell giving the failure.
  - **Exit status:** 1 if any cell inside a box fails.
- **`./regress` step 4** runs the shmoo for `good` and `marginal` and diffs each `shmoo.csv` against `regression/baselines/shmoo_<die>.csv` (plus `good_results.csv` as before). `--accept` copies all three. `out/shmoo_<die>.svg` is kept for the PR.
